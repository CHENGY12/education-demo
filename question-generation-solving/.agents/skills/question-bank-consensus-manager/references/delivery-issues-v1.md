### 问题 1　打包混入 macOS 资源叉文件

**分布**：`nj_chem.tar`、`cn-nanjing-g11-2026-数学.zip` 均有。

`nj_chem.tar` 中除 213 个 `questions.jsonl` 外，另有 `._questions.jsonl` 85 个（AppleDouble 资源叉，二进制内容）、`.DS_Store` 及 `._.DS_Store` 各 4 个、各级目录的 `._<目录名>` 条目。

`cn-nanjing-g11-2026-数学.zip` 中另有完整的 `__MACOSX/` 目录树（含 163 个 `._questions.jsonl`），且顶层目录名为 `cn-nanjing-g11-2026-数学-all-teacher-pass copy`，带 macOS 副本后缀 ` copy`。

入库流程按 `**/*.jsonl` 递归读取题目文件，`._questions.jsonl` 会被当作题库读取并导致 JSON 解析失败。

**规范**：macOS 下打包使用


或打包后清除：`find . -name '._*' -delete && find . -name '.DS_Store' -delete`。

`nj_chem.tar` 与 `cn-nanjing-g11-2026-数学.zip` 均无 `manifest.json`，无法核对文件完整性与题目计数。

### 问题 3　化学键的连字符被写进下标

**分布**：78 道题 / 168 处，涉及 21 个节点。集中在有机结构式（烷烃命名、聚合物重复单元）。

| 位置                                      | 处数 |
| ----------------------------------------- | ---- |
| `化学/4月阶段性检测_13/questions.jsonl` | 58   |
| `化学/4月阶段性检测_9/questions.jsonl`  | 24   |

| `化学/5月期中检测_11/questions.jsonl`   | 14   |
| `化学/4月阶段性检测_1/questions.jsonl`  | 10   |
| 其余 16 个节点                            | 43   |

连接原子的键线短横被写进了下标的花括号内：

| 现状                      | 渲染结果                                               | 规范写法                  |
| ------------------------- | ------------------------------------------------------ | ------------------------- |
| `CH_{3-}CH_{2-}CH_{3}`  | CH₃₋CH₂₋CH₃（下标显示为「3−」「2−」，键线消失） | `CH_{3}-CH_{2}-CH_{3}`  |
| `[-CH_{2-}CH_{2}-]_{n}` | 重复单元的主链断开                                     | `[-CH_{2}-CH_{2}-]_{n}` |
| `C(CH_{3})_{2-}CH(...)` | 取代基个数与键线粘连                                   | `C(CH_{3})_{2}-CH(...)` |

**位置示例**：`化学/4月阶段性检测_13/questions.jsonl` 第 2 行，`$\mathrm{CH_{3-}CH_{2-}C(CH_{3})_{2-}CH(CH_{3})-CH_{2-}CH_{3}}$`。

KaTeX 对此不报错——下标 `{2-}` 是合法语法，只是含义被改变，属渲染成功但结构式已错。

**规范**：下标花括号内只放数字。键线短横写在花括号之外。

### 问题 4　`\text{}` 内使用下标

| 现状                                        | 规范写法                                                      |
| ------------------------------------------- | ------------------------------------------------------------- |
| `$\xrightarrow{\text{NaOH、H_{2}O_{2}}}$` | `$\xrightarrow{\mathrm{NaOH}\text{、}\mathrm{H_{2}O_{2}}}$` |

**规范**：反应条件中，化学式部分用 `\mathrm{}`，中文与中文标点用 `\text{}`，两者分开写。

### 问题 6　化学式未使用正体

**分布**：76 道题，涉及 23 个节点。全包 94% 的题已正确使用 `\mathrm{}`，其余为遗漏。

数学模式下字母默认为斜体（表示物理量）。化学式必须正体，否则与物理量混淆。

| 现状                       | 渲染结果                   | 规范写法                                              |
| -------------------------- | -------------------------- | ----------------------------------------------------- |
| `$CaCl_{2}(s)$`          | *CaCl₂*(*s*)（斜体）  | `$\mathrm{CaCl_{2}(s)}$`                            |
| `$2Fe^{3+}+Cu=2Fe^{2+}$` | 全部斜体                   | `$2\mathrm{Fe}^{3+}+\mathrm{Cu}=2\mathrm{Fe}^{2+}$` |
| `$r(Si)>r(Cl)$`          | 半径符号与元素符号同为斜体 | `$r(\mathrm{Si})>r(\mathrm{Cl})$`                   |

**规范**：

- 元素符号、化学式、离子符号、状态符 `(s)(g)(l)(aq)` 一律置于 `\mathrm{}` 内。
- 物理量符号保持斜体，不加 `\mathrm{}`：`$V$`（体积）、`$K_{sp}$`（溶度积）、`$\Delta H$`（焓变）、`$c(\mathrm{H^{+}})$`（浓度 c 斜体、离子正体）。
- 同一公式内两者并存时分别处理，如 `$n(\mathrm{CO_{2}})=0.2\ \mathrm{mol}$`。

### 问题 9　解析使用 Unicode 数学符号而非 LaTeX 命令

### 问题 10　ANSI 终端转义码写入数据，原字符丢失

**位置**：`5月期中检测_10/questions.jsonl` 第 6 行，`pb_数学_5月期中检测_10_gen_8e34782d0595` 的 `prompt`。

```
现状：在正方体 $ABCD-A_1B_1C_1D_1$ 中，取 $A$ 为原点，$<ESC>[1m<ESC>[0m$ 轴、$y$ 轴、$z$ 轴分别沿 $AB,AD,AA_1$ 方向。
应为：在正方体 $ABCD-A_1B_1C_1D_1$ 中，取 $A$ 为原点，$x$ 轴、$y$ 轴、$z$ 轴分别沿 $AB,AD,AA_1$ 方向。
```

`<ESC>[1m` 与 `<ESC>[0m` 是终端「加粗」「重置」的 ANSI 控制序列，说明生成链路某处把带颜色的终端输出直接写进了数据文件。**原有的 `x` 已被覆盖，字符本身已丢失**，只能依上下文人工补回。

此类问题渲染不报错（转义码被清除后残留 `[1m[0m`，属合法数学内容），自动校验难以发现。

**规范**：写入数据前关闭终端着色输出（如设置 `NO_COLOR=1`、或写文件时不经过带 ANSI 着色的日志通道）。交付前检查文件中不含 `\x1b`。

## 三、题目结构

### 问题 13　一题存在两个正确选项

**位置**：`化学/4月阶段性检测_13/questions.jsonl`，`pb_化学_4月阶段性检测_13_gen_012`。

题干为烷烃 `CH_{3}-CH_{2}-C(CH_{3})_{2}-CH(CH_{2}CH_{3})-CH_{2}-CH_{3}` 的系统命名。

| 选项 | 内容                  | 判定                                      |
| ---- | --------------------- | ----------------------------------------- |
| A    | 3-乙基-4,4-二甲基己烷 | 编号方向错误，位次组 {3,4,4} 劣于 {3,3,4} |
| B    | 4-乙基-3,3-二甲基己烷 | 标注答案                                  |
| C    | 3,3-二甲基-4-乙基己烷 | **与 B 为同一名称**                 |
| D    | 3-乙基-3,4-二甲基庚烷 | 母体误判为庚烷                            |

B 与 C 的主链、位次完全相同，差别仅在取代基的书写次序：C 依中文命名习惯将较简单的甲基列在前，B 依英文 IUPAC 的字母序将乙基列在前。两者描述同一化合物，同为正确答案。

**规范**：干扰项不得与正确答案指向同一化合物。涉及命名次序的题目，四个选项应在主链、位次或取代基种类上存在实质差异。

### 问题 14　干扰项按教材口径同样成立

## 六、句末标点规范

本节规定题干 / 选项 / 解析的**句末标点**（中文全角）。清单一至五未覆盖此类；平台已冻结句末标点引擎 v3.1，交付内容应据此到位。

### 规则

| 对象                                 | 规则                                                                                                                                                                                                                                                                                                              |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **题干·选择题**（≥2 个选项） | 引出型句尾（`…的是` / `正确的是` / `分别为` / `包括`）→ **冒号 `：`**；疑问型句尾（`…是什么` / `多少` / `如何变化` / `吗` / `呢`）→ **问号 `？`**；**作答括号 `（ ）` 结尾 → 保留括号、其后不加任何标点**（不加句号，也不加冒号）                                  |
| **题干·解答题**（无选项）     | 中文指令 / 陈述句 →**句号 `。`**；以冒号引出下文（`求：` / `如下：` / `流程如下：` / `回答下列问题：`）→ **保留冒号**；多行 Markdown 表格 / 附录 / 参考公式结构 → 末尾**不补**句号                                                                                                 |
| **选项**                       | 完整陈述句（有主语 + 判断谓语，或`如果…则` / `当…时` / `因为…所以` 复句）→ **句号 `。`**；短语 / 动宾 / 方向大小状态 / 纯公式 / 纯数值 / 答案片段（`恒等于常数` / `只能是 1 个` / `向左运动`）→ **不加**；**同一题 A–D 风格一致**（要么全部加句号，要么全部不加，不得混排） |
| **解析**                       | 完整中文陈述 →**句号 `。`**；末尾为块级公式 `$$…$$` / `\[…\]` → **不加**                                                                                                                                                                                                                    |
| **全局**                       | 只补**全角**中文标点；已有终止标点 `。！？：……` **不叠加**；公式 `$…$` / `$$…$$` **内部标点不动**；本轮**不做**全半角转换                                                                                                                                                       |

原则：**「有判断语义」≠「完整陈述句」**。拿不准的短句宁可不加，交平台灰区人工，不要为求整齐给答案短语硬加句号。

### 与平台引擎的关系

平台构建时用 v3.1 引擎**只自动补高置信**部分（引出句冒号 / 强复句句号 / 作答括号去多余标点 / 直接疑问句问号）；**灰区（仅含单个逗号的选项、省略型答案短语、疑问与引出难以区分的题干）一律不改**。因此**交付时须按上表把标点写到位**——灰区题目的标点缺失，引擎不兜底。

### 顺序（关键交互）

**句末标点规范化依赖 `$…$` 定界符保护公式，必须在问题 3–12（公式定界 / 控制字符 / Unicode 符号 / 裸公式）与第 4 项（`A.` 开头裸选项）修复之后执行。** 裸公式、Unicode 数学符号、ANSI / 控制字符、混入题干的裸选项行都会让题干 / 选项拆分和句末判断误伤，须先清理再过标点。

### 交付前校验项（接第五节，新增 20–24）

```
20. 选择题题干（≥2 选项）非作答括号结尾时，句尾为 ：或 ？，不为 。
21. 作答括号（ ）/( ) 之后无 。/：/，
22. 同一题选项 A–D 句末标点风格一致（全句号或全不加）
23. 无异常连续/错配标点：grep -P '：。|。：|。。|？。|！。|，。|：：' questions.jsonl 无输出
24. 无跨公式叠加标点（公式内 . 紧接公式外 。），抽查解析末尾 $$…$$。 形态
```

> 第 23、24 项为高发盲区：`试求：。`、`$$…$$。`、`（ ）。` 等在自动补标点时最易产生，源头交付也应自查，勿依赖引擎兜底。

### 边界说明

问题 6（化学式正体 `\mathrm{}`）、问题 12（公式内中文用 `\text{}`）属**公式内部格式**，平台标点引擎**不触碰**（在保护区内），仍由供应商在源头修正。**引擎只规范公式外的句末标点；公式内格式全靠交付方保证。**

### 问题 19　解析结论措辞不统一，导致自动校验漏检

平台闸门用正则检测「解析结论字母 ≠ `answer`」（学生选对却看到解析说选别的）。原正则只认「故选X / 应选X / 因此选X / 所以选X / 答案为X / 正确选项为X」，**认不出下面这些同样是结论的写法**：

```
…化简得 cos∠F₁AB=(1+x+2x²)/(1+3x)，对应A。
…共 2 个，选C。
…因此正确的是 B。
…故不正确的是 D。
```

本轮实测：平台侧调整选项顺序时，这类写法漏改了 **61 处**（旧正则一处都没抓到）。闸门已于本轮扩充正则（见 `backend/pipeline/practice_bank_ingest.py` 的 `_CONCLUSION_RE`），扩充后在全部数据集 12676 题上误报 0。

**规范**：解析结论统一写作 **「故选X。」**，放在解析末尾。避免用「对应X」「即X」指代选项——这些写法在几何题里会和点 A、角 B 混淆（实测 `x=1对应A` 中的 A 是双曲线右顶点，不是选项 A）。
